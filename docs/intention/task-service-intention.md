# 任务服务范围与决策

## 定位

本项目提供面向通用 MCP 调用方的本机 Gemini 问答服务。Codex 只是其中一个调用方，服务不依赖任何专有会话、提示方式或界面；CLI 与 MCP 共用同一持久化队列。

使用方式是：通过本机已登录的固定 1.16.0 Windows 桌面客户端新建对话或续接本服务任务，提交任务文本和调用方明确提供的 TXT 材料，等待并取回完整回答。Gemini 不执行本地 shell，也不编辑本地文件。本项目是问答调用端，不是通用自主编码代理，也不把客户端侧栏入口包装成业务接口。

## 已决定策略

| 事项 | 决定 |
|---|---|
| 服务对象 | 任意兼容 MCP 调用方；不以 Codex 专有能力为前提 |
| 默认模型 | 未指定时一律使用 4 Hydrogen，不沿用页面当前选择，也不改成“保持当前模型” |
| 模型选择 | 允许选择当前页面菜单实际暴露的其他模型，按唯一名称或完整条目标识解析，不使用永久固定枚举 |
| 失败模型 | 不自动路由、不自动降级、不切换模式、不创建补做任务；缺失、歧义、禁用、锁定或升级入口明确失败 |
| 页面依据 | 以实页调查支撑模型、布局和控件识别，避免在各层重复硬编码 |
| 会话模式 | 对话/任务模式属于会话，中途不能切换；续聊保留已有会话模式；再次传入 chat/task 不会切换，调用方应核对返回的实际模式 |
| 会话范围 | 支持新建对话和本服务任务的续聊；全部历史会话的列出、查找、读取、重命名和删除不在范围 |
| 生命周期 | 提交、排队、准备、发送确认、生成、完成、失败、部分回答和发送状态不明分别表达；恢复优先读取原会话 |
| 并发 | 同时生成上限为 3（含准备阶段）；不同对话可在上限内并行，同一会话已有生成时拒绝第二轮 |
| 后台健康 | supervisor 与 worker 分离；进程、桥、页面和任务进展分别报告，进程存在不等于实际可工作 |
| 能力目录 | 只报告当前页面实际观察到的模型、模式和思考选项；不跨请求缓存，查询不发送、不切选项、不覆盖草稿 |
| 状态表达 | `activity` 只解释已有任务或健康证据，提供下一步动作，不改变执行状态、预算、重试和完成判定 |
| 文档 | 只保留当前权威现状；过时规则直接清理，不归档 |

默认模型是产品决策；页面实际提供哪些模型是调查事实，两者分开。页面出现新模型应能被发现；默认 Hydrogen 消失或改名时应报告不匹配，不自行替换为另一个模型。

## 服务对象与存续关系

| 对象 | 含义 | 存续范围 |
|---|---|---|
| Gemini 对话 | 保存上下文与多轮消息，具有固定模式 | 长期存在于 Gemini，不要求本地页面常驻 |
| 一轮调用 | 一次任务文本及其回答，关联明确对话和本轮回答归属 | 发出到完成、失败或待处理，并保留结果 |
| 多步任务 | 调用方根据前一步结果继续下一轮；服务提供续聊入口，不内置业务工作流引擎 | 跨多轮，通过父任务关联 |
| 执行页面 | 承载当前活动对话的临时资源，不等同于对话身份 | 服务当前活动任务，完成后释放或复用 |
| 后台进程 | 调度、观察、持久化和恢复 | 独立于某次 MCP 等待连接 |

对话内串行、不同对话有限并行。历史会话不常驻页面；活动任务占用有限页面资源，结束后释放，续聊时按会话身份重新打开。等待结束、当前一轮结束和多步任务结束是不同概念；停止等待不取消或重发任务。

## 可靠性要求

- 当前一轮回答完整且归属正确；生成信号矛盾、迟到通知和旧回答不能触发完成。
- 调用方退出、连接断开或后台重启不自动重发；发送状态不明时只查询或恢复原会话。
- 正常安静、等待结束证据和观察失联分别表达；没有新文字不单独判定失联。
- 实时能力来自当前页面并注明观察状态、来源与时间；菜单未展开不能推断账号没有模型。
- 查询能力目录不干扰活动任务、不改变模型或思考设置、不覆盖草稿。
- 进程存活、桥连通、页面可用和任务进展分别报告。

## 不在范围

- 本地 shell、文件编辑、通用自主编码代理或任意浏览器执行工具。
- 全部历史会话管理；本服务保存的任务续聊除外。
- 自动模型路由、自动保底、自动补做或自动重试发送状态不明的任务。
- PDF、图片或其他非 TXT 附件。
- 多账号轮转、云端中转、自动接受新条款、导出 Cookie 或浏览器凭据、修改 VPN。
- 主动停止生成；`release` 只关闭任务生命周期，不终止已发送的生成。
- 分发 Gemini 客户端、附带登录材料或自动适配未知客户端版本。

## 成功标准

- 同一 MCP 行为可由不同兼容调用方使用，不依赖 Codex 专有能力。
- 默认选择和自主指定都能解释“请求了什么、页面选中了什么、哪些仍无法核实”。
- 新模型名称和菜单排列变化不要求在各层重复修改固定枚举。
- 普通模型、锁定条目和升级入口不混为一谈。
- 能力清单和调查结论有来源与时间；采集失败不伪造清单。
- 文档中的已验收结论不超出 [验证状态](../../ACCEPTANCE.md) 记录的范围。
