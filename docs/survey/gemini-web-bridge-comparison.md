# Gemini 网页桥接方案对照与复用判断

调查日期：2026-11-17。外部仓库按下表提交固定核查；在线页面与仓库后续版本可能变化。

## 结论

保留已登录客户端。当前路线直接复用现有登录、在后台发起任务，避免额外的浏览器会话与授权步骤；三任务并发已有项目实测依据。未找到已证明能够完整替换当前方案、同时降低操作和维护成本的现成项目。

最值得借鉴的是实时能力目录、模型证据的有效期，以及可理解的诊断和恢复验收。页面独占、任务账本、事件补报已经具备，无需重造。

对照只读外部源码、设计材料和本项目实现；没有安装或执行外部项目，没有发送新的 Gemini 消息，没有修改运行代码和客户端补丁。外部能力属于源码可见行为，不等于已在任一账号实测。建议不构成新的接口规格。

## 目标与接入方式

目标是在后台可靠发起任务并取得对应完整回答，尽量减少人工准备。Playwright、浏览器扩展、客户端内部桥接都是实现手段。

Electron 的 WebContentsView 承载 WebContents，当前客户端内仍是 Gemini 在线网页。浏览器项目的页面交互经验可借鉴，差别在宿主生命周期、权限、安装和升级。[Electron 官方说明](https://www.electronjs.org/docs/latest/api/web-contents-view)

Playwright 的持久化上下文可以保存会话数据；反复手动登录不是所有实现的必然行为。这不改变继续使用客户端的决定。[Playwright 官方说明](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-persistent-context)

| 路线 | 对本项目的价值 | 维护代价 |
|---|---|---|
| 客户端内部桥接 | 直接复用当前登录，与日常浏览分开，已有隐藏页面并行基础 | 客户端补丁、预加载配置、在线网页变化；不能保证永不重新登录 |
| 浏览器扩展 | 复用登录，可参考标签页所有权和能力发现 | 扩展安装、连接与后台生命周期 |
| 持久化浏览器自动化 | 便于复现页面操作，支持保存登录 | 浏览器资料及启动管理、页面变化；是否打扰由实现决定 |
| 逆向网页协议 | 避开 DOM 控件，可研究会话和模型身份 | Cookie 更新和非公开协议变化；引入会改变当前不导出 Cookie 的边界 |

Chrome 扩展后台 service worker 可能被终止，需要处理持久化与恢复；扩展不天然比客户端稳定。[Chrome 官方说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

### Walkoud：目标接近，结束判定不宜移植

`chrome-extension/content.js` 的 `waitForNewResponse` 用 MutationObserver 观察文字，三秒不变便返回；总超时仍调用 `extractLatestResponse`，找不到回答时可返回整页末尾文本。静态上存在把生成暂停、旧回答或其他页面文字当结果的风险，未运行反例。

`background.js` 通过 requestId 关联响应，断线时暂存一份 `pendingResponseObj`；这是补送结果，不等于重发问题，但也不是多任务持久恢复队列。

可以借鉴连接、页面和模型状态的可见性；不移植宽泛按钮兜底、整页文本兜底或单凭稳定文本完成。仓库元数据未确认复用许可证，直接复制前须核验。

### HuggingBunny：持久化登录可参考，采集仍简单

`server.js` 使用单个全局页面和持久化 Chrome profile；初次设置打开浏览器，后续复用登录，说明浏览器自动化并非每次都要重新授权。

`waitForResponseComplete` 读取最后一条回答，检查加载状态和连续稳定次数；超时跳出循环后仍返回已有文字。它缺少本项目同等的本轮标记与回答槽位归属校验，不能直接替换当前三任务执行链路。MIT 许可不代表实现就适合移植。

### Gemini Web Bridge：能力目录、证据失效与存活判断最有参考价值

`cloudflare-worker/src/index.js` 定义 `list_bridge_models`，向调用方提供当前发现的模型及验证信息。`dist/extension/evidence-registry.js` 区分选择器证据和生成证据，`invalidateAll` 清除旧生成证据和映射版本；单有菜单证据不能恢复“已验证”。这是可学习的结构，不能因此断言其实际模型识别始终正确。

`cloudflare-worker/src/liveness.js` 将“连接安静”和“已发探测却未应答”分开，Worker 导入并使用这些判断。本项目已有观察器 ping 和无进展诊断，可补验收和状态表达，不需再造心跳系统。

`native-recovery.js` 包含点击重试、重新发起的恢复路径，与本项目只恢复读取、不自动重发的边界冲突，不采用。

该仓库文档与源码存在时效差异：健康恢复 ADR 仍标 Proposed，正文称缺少心跳，当前代码已有探测。README 的单并发描述也不能概括代码按 scope、连接和在途任务选取执行对象的行为；不能仅据 README 概括其全局上限。API 元数据未确认许可证，不直接复制代码。

### Gemini-API：学习身份模型，暂不引入协议

`types/availablemodel.py` 分开保存不透明 model_id、显示名称、描述、可用性和别名，从 RPC 构造模型；`components/chat_mixin.py` 通过聊天 ID 与服务端轮次元数据读取和管理会话。值得学习身份与展示分离，不把当前名称固定成永久集合。

它是协议库，不是完整 MCP 任务服务，需要 Cookie 认证和协议维护；重试机制不能未经发送边界分析便移植。许可证为 AGPL-3.0，直接引入或复制需要评估兼容性。当前仅借鉴思路，不导出凭据、不引入依赖；全部历史管理仍不在范围。

### Tandem：页面归属可参考，断连释放不能照搬

`src/host.js` 按 sessionId 管理标签页 claim，为每个会话固定默认页面；显式 tabId 也校验所有权。这支持每个动作绑定明确页面，避免跟随当前活动页面。

其租约清理与调用方断连会释放 claim。本项目需要在调用方关闭后继续执行，不能把连接断开或租约到期当作生成结束，也不能把仍生成的页面交给下一任务。

本项目已有准备起独占页面；增量是更清楚地展示归属，不是新增一套锁。README 声称 MIT，API 元数据未规范识别；未来复制前应核对 LICENSE 与来源链。

|---|---|---|

| 原生通知的绑定范围 | 已在隔离 preload 的原厂 send 调用处捕获开始上下文，结束沿用相应上下文；私有通知严格校验文档、绑定代次、任务和顺序；原厂无绑定渠道仅诊断 | 旧绑定、旧任务和乱序反例已拒绝；实际客户端挂钩生效，任务记录有效通知，不在接收时补当前任务号作为归属证明 |
| 页面故障与模型正常回答的区分 | 页面故障识别主要处理登录、网络、地区和弹窗；完成状态表示这轮回答收取完成，不证明回答满足业务目标 | 应依据错误气泡结构等页面事实区分平台失败，正常拒答仍应交付。不能因回答引用“出错了”等文字就改成执行失败，也不自动点击重试 |

## 保留范围与复用结论

保留任务账本、唯一任务标记、严格回答配对、有限并发、页面独占和完成回收。暂不引入云端中转、多账号轮转、API 自动保底、自动点击重试、通用浏览器执行工具或全部历史管理；这些尚未证明能降低操作成本，还会扩大维护范围。

上表五个固定提交中，没有找到适合直接替换整个执行链路的已验证依赖；这不代表 GitHub 不存在其他方案。当前适合做机制借鉴，新增能力按现有规格和验收流程推进。
