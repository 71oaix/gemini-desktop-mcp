# 实时能力目录与任务状态表达

本文定义 `gemini_capabilities` / CLI `capabilities` 与任务 `activity` 的稳定行为契约。实现或修改这些行为时应满足本文约束，并在 [验证状态](../../ACCEPTANCE.md) 中记录实际验证范围。

任务 `activity.state` 的稳定标识为 `queued / preparing / submitting / generating / quiet / awaiting_completion / observation_lost / reconnecting / partial / uncertain / needs_user_action / completed / failed`；健康结果另有 `idle / working / not_running / stopped`。未归类状态以原 status 和 error_code 为准。

## 目标与边界

调用方可以查询当前页面实际暴露的模型及思考设置，并理解任务正在等待什么。服务继续使用已登录客户端与现有观察层，面向通用 MCP 调用方，CLI 提供相同入口。

沿用默认 Hydrogen、动态选择、会话模式不可中途切换、不自动降级、不自动补做、不重复发送的约束。本契约不包含历史会话管理、模型路由、主动停止生成或新增后台监控服务。

## 能力查询

无参数 `gemini_capabilities`，CLI 为 `capabilities`。返回结构包含查询状态、是否实际观察、采集时间、来源、模型条目、当前模式与思考能力及阻塞原因。模型条目保留当前页面标识与名称，区分当前选中、禁用、受限、不可用；可用于自主选择的 selector 不依赖固定名单。菜单存在不等于本轮实际推理模型已核实。

只在已绑定、可用的空闲主页面，没有草稿、上传、弹窗或用户已打开的菜单时查询。已有活动任务、查询或菜单操作时返回 busy，不打开菜单。阻塞或失败时不返回伪造清单和静态别名；不使用跨请求缓存。模式当前不可观察时为 unknown，不根据模型或名称猜测；两种受支持模式与会话不可切换属于接口约束，不冒充当前页实测结果。

查询在任何异步页面动作之前独占菜单检查范围；与提交、恢复和其他设置动作互斥，不能在“先检查空闲、后等待”之间让任务抢用同一页面。等待使用现有观察器推送，保持有限期限，不周期读取整页。只允许打开或收起菜单，不点击模型或思考选项，不发送、导航或新建会话。清理只针对本次打开的菜单，不处理用户新出现的弹窗；用户操作导致中断时交还控制。查询失败或结束后释放自己的占用，并说明清理是否完成。

思考等级只报告当前页实际观测到的选项；当前明确为任务模式且不暴露菜单时报告 `not_exposed`，不能伪造低中高。当前模式未知且无入口时报告 `unknown/unavailable`。菜单异步出现需等待；观察数据被截断、页面换文档或模型信息缺失时不得报告 `ready`。

`ready` 表示模型菜单已实际观察且本次菜单已确认收起；思考部分仍可独立为 `unknown`，不能因为这一部分未知而伪造选项。最多接受 40 个完整模型或思考条目，超过限制明确失败，不截断后声称完整；selector 不在传输层截短或改写。菜单收起优先使用唯一遮罩，嵌套模型与思考菜单可使用唯一模型菜单开关，不能用点击已选项代替收起。

## 状态表达

在现有 status/result/wait 与 health 结果上追加 `activity`，保留原有 status、phase、错误码、重试和恢复行为。`activity` 提供稳定状态标识、简明说明、原因和下一步动作，并注明依据来自已保存任务证据或本次健康探测。不能凭持久化记录冒充实时探测成功。

| 证据或阶段 | 表达与建议 |
|---|---|
| 排队、准备、发送确认 | 分别表达阶段；等待后台，不要求重交 |
| 生成中且没有失联证据 | 正在生成或思考；等待。没有新文字不单独判定失联 |
| 观察器可响应但回答尚缺结束证据 | 等待完成确认；保留原任务继续观察 |
| 空闲 ping 成功但暂时无进展 | 正常安静/等待进展；不猜测已经结束 |
| ping 失败或明确观察器断线 | 观察连接异常；恢复原任务读取，禁止建议重新提交 |
| 传输断开、有限恢复中 | 正在重连/等待重连；保持原任务编号 |
| 登录、草稿冲突等需要人工处理 | 显示具体阻碍，处理后 connect，不覆盖草稿 |
| 已完成、失败、部分回答、发送状态不明 | 保持各自含义，不将有文字或等待超时标记为成功 |

终态优先于陈旧连接字段，观察失败优先于“已有回答”。health 区分后台、桥、页面就绪及当前是否有任务，不能把 idle 当失联。时间字段只用于解释，不能新增“多久无文字就失败”的阈值。

## 实现与验收

复用桌面桥受限菜单动作、动态模型解析、观察器 `waitFor`、现有任务账本及健康结果。状态表达使用不读页面、不改队列的纯映射，不建立另一套状态机。

验收至少覆盖：新模型无需改名单即可查询；受限条目正确；忙碌、草稿或已开菜单时无点击；查询与提交竞争不抢页面；失败释放、换文档拒绝；未暴露思考入口不伪造；查询结束菜单收起且模型、思考、模式不变。状态反例覆盖静默生成、等待完成、ping 失败、重连、人工处理及带陈旧连接字段的终态。

真实验证使用已登录客户端：空闲查询并核对前后设置；必要的一条短任务在生成时查询返回 busy，且任务正常完成；核对 MCP 工具、CLI 与状态表达。真实断网和任意崩溃组合不因存在 `activity` 字段而视为已验收。
